Scheduled Task hijack — pivot Linux → root no Windows

Linux → Windows ALTO pivotingreuso de senhaScheduled TaskCWE-732

resumo

Cadeia entre dois hosts: credencial de banco do GLPI num Linux é reusada numa conta Windows; acesso à estação via TeamViewer como usuário comum; privesc abusando de uma Scheduled Task que roda como Administrator apontando para um binário gravável por qualquer usuário local.

a cadeia

  1. 1
    Foothold Linux + credencial do GLPI

    SSH no host Linux; /etc/glpi/config_db.php revela a credencial de banco do GLPI (mascarada).

  2. 2
    Reuso de senha → Windows

    A mesma senha funciona na conta Windows suporte. Tentativa de PrintNightmare foi descartada (STATUS_PASSWORD_EXPIRED + RestrictAnonymous bloqueando troca via SAMR) — mitigação real do alvo, não limite de ferramenta.

  3. 3
    Acesso à estação via TeamViewer

    Porta 5938 aberta na LAN; login como suporte (usuário não-admin). Exploit público de TeamViewer 11 checado e descartado (versão do alvo diferente).

  4. 4
    Enumeração → Scheduled Task vulnerável 
    schtasks /query /fo LIST /v
# Task \Backup → executa como: Administrator
#   binário: C:\Suporte - Tarefas\Backup\tftpd64.exe
icacls "C:\Suporte - Tarefas\Backup\tftpd64.exe"
# → BUILTIN\Usuários:(I)(F)   ← Full Control p/ qualquer usuário
  5. 5
    Hijack do binário → execução como Administrator

    Sobrescreve o .exe pelo payload. Armadilha: a instância TFTP de longa duração travou o disparo — resolver com /end antes do /run:

    schtasks /end /tn "\Backup"
schtasks /run /tn "\Backup"   # agora dispara como Administrator

mecanismo — por que funciona

O serviço Schedule roda como SYSTEM e impersona o token do usuário configurado na task (Administrator) ao lançar o processo. Ele não revalida se o binário no path continua confiável — executa o que estiver lá. Full Control inclui WRITE_DAC/DELETE, então o binário inteiro pode ser substituído.

É a mesma família de unquoted service path e DLL hijacking: um processo de alto privilégio confia em um recurso gravável por um usuário de menor privilégio (CWE-732).

detecção / mitigação

  • ACL correta: o binário de uma task que roda como Administrator não pode ser gravável por Users.
  • Não reusar credenciais entre serviços e hosts; expirar e rotacionar.
  • Detecção: Event ID 4698/4702 (criação/alteração de task) e gravação em binário de task privilegiada (Sysmon Event ID 11) são sinais diretos.
