Cartão Seguro — SSTI até root

HackAcademy CRÍTICO SSTI Jinja2RCEsecret disclosuredoas privesc

resumo

App Flask com um formulário público "veja se seu cartão vazou". O campo nome é concatenado numa string de template Jinja2 antes do render — SSTI não autenticado que vira RCE, vaza a SECRET_KEY e, com doas permissivo, escala a root. Rota de exploit de kernel existia no host mas foi descartada como desnecessária.

a cadeia

  1. 1
    Recon — fingerprint da stack

    Header Server: Werkzeug/Python → Flask. Rota /admin descoberta por fuzzing.

  2. 2
    SSTI confirmado

    Input refletido sem sanitização. Payload canônico confirma avaliação server-side e vaza o objeto de config:

    POST /  nome={{7*7}}      → 49
POST /  nome={{config}}   → Config completo + SECRET_KEY: [mascarada]
  3. 3
    Escalonar SSTI → RCE

    A partir de um objeto do contexto, subir a cadeia de classes do Python até os.popen:

    nome={{config.__class__.__init__.__globals__['os'].popen('id').read()}}
# → uid=...(apps) — execução de comando confirmada
  4. 4
    Pós-exploração

    Com RCE como apps: dump do SQLite (cartoes em texto claro — CWE-312) e enumeração de privesc. doas aparece como caminho mais limpo que o kernel exploit pré-posicionado.

  5. 5
    Privesc — doas permissivo → root

    Regra de doas sem restrição de comando para o usuário apps:

    echo "cat /root/flag" | doas   # executa como root
# flag: EXPM{mascarada}

mecanismo — por que funciona

SSTI: o dado do usuário é tratado como sintaxe de template, não como valor. render_template_string("Olá " + nome) faz o Jinja2 avaliar qualquer {{ ... }} enviado. A diferença está em passar o nome como variável de contexto, não como parte da string do template.

SSTI → RCE: Jinja2 roda em Python; a partir de qualquer objeto dá para subir por __class__ → __mro__/__globals__ até alcançar os e executar comandos.

SECRET_KEY: ela assina (HMAC) o cookie de sessão — garante integridade, não sigilo. De posse dela, um atacante forja qualquer sessão válida (ex.: flask-unsign), burlando autenticação em rotas que confiam em session.

doas: uma regra sem cmd específico é equivalente a dar root; qualquer foothold como apps escala trivialmente.

detecção / mitigação

  • render_template() com arquivo fixo + nome como variável de contexto — nunca concatenar input na string do template.
  • Rotacionar e nunca fixar a SECRET_KEY; carregar de env/secret manager com alta entropia.
  • Regras de doas/sudo sempre com comando específico, nunca permit nopass genérico para serviço.
  • Dados de cartão nunca em texto claro (PCI-DSS).
  • Detecção: processos filhos anômalos sob o usuário do app web (sh/id saindo de um worker Flask) são forte indício de RCE.
