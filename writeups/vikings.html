Vikings — da web ao root

VulnHub CRÍTICO dir enuminfo disclosurepassword cracking esteganografiacred vazadaRPyC privesc

resumo

Boot2root da VulnHub. O caminho encadeia enumeração web → um bloco Base64 que esconde um ZIP com senha fraca (quebrada no John) → esteganografia numa imagem JPEG escondendo credenciais → acesso SSH (foothold) → privesc por um serviço RPyC rodando como root e sem autenticação.

a cadeia

  1. 1
    Recon — nmap

    Dois serviços: SSH (OpenSSH 7.6p1) e HTTP (Apache 2.4.29). O script http-ls revela o diretório /site/, ponto de partida.

    nmap -Pn -p- -n -A -sS -sV 192.168.56.101
  2. 2
    Enumeração de diretórios

    Fuzzing em /site/ acha war.txt (HTTP 200), que aponta para o diretório oculto /war-is-over.

    gobuster dir -u http://192.168.56.101/site/ \
  -w common.txt -x php,txt,bak,zip
  3. 3
    Info disclosure — Base64

    /war-is-over devolve um bloco enorme em Base64. Base64 não é criptografia — é codificação reversível; decodificar gera um ZIP protegido por senha.

    curl http://192.168.56.101/site/war-is-over/ | base64 -d > descripto
  4. 4
    Senha fraca — John the Ripper

    A senha do ZIP era fraca: extraída com zip2john e quebrada por dicionário (rockyou).

    zip2john descripto.zip > hash.txt
john hash.txt --wordlist=rockyou.txt   # → [senha — mascarada]
  5. 5
    Esteganografia — ZIP embutido em JPEG

    Dentro do ZIP havia a imagem king (JPEG) com um ZIP concatenado após o fim da imagem (binwalk acha a assinatura no offset 0x15D03F). Recortar e extrair revela as credenciais do usuário floki.

    binwalk king
tail -c +1429568 king > king.zip
unzip king.zip && cat user   # → floki : [mascarada]
  6. 6
    Foothold — SSH como floki

    Login SSH com as credenciais da imagem (Ubuntu 18.04). Flag de usuário em /home/ragnar/user.txt.

    ssh floki@192.168.56.101
  7. 7
    Privesc — RPyC como root sem autenticação

    Um serviço RPyC (Remote Python Call) roda como root e aceita conexões sem autenticação = execução de código Python como root. floki não podia executar o python3.6 do ragnar (permissões 754); copiar o binário cria um arquivo cujo dono é floki, com permissão de execução. Com um Python utilizável, conecta no RPyC e roda código como root → shell SUID.

    ps -eo pid,user,cmd | grep -i rpyc
cp /usr/bin/python3.6 /tmp/py && chmod +x /tmp/py
# conecta no RPyC, executa como root, gera /tmp/rootbash SUID
/tmp/rootbash -p   # uid=0 (root) → /root/root.txt

mecanismo — por que funciona

Base64: é codificação reversível, não criptografia — qualquer "segredo" guardado assim está em texto claro para quem decodificar.

Esteganografia / arquivo concatenado: um JPEG válido continua válido com outro arquivo colado após o marcador de fim da imagem. O binwalk encontra a assinatura do ZIP num offset; você recorta a partir dali com tail -c e extrai.

RPyC como root: o serviço executa objetos/código Python no próprio processo. Rodando como root e sem exigir autenticação, qualquer cliente executa código como root. Classe: autenticação ausente em serviço crítico (CWE-306). O truque do cp contorna a permissão 754 — copiar gera um novo arquivo de dono floki, que então pode executá-lo.

detecção / mitigação

  • Nunca rodar serviço como root — privilégio mínimo. Exigir autenticação/ACL no RPyC ou restringir a escuta a localhost.
  • Senhas fortes; não guardar segredos em arquivos ou imagens acessíveis — usar cofre de segredos.
  • Não expor dado sensível no web; remover arquivos como war.txt e desabilitar listagem de diretório.
  • Detecção: processo python filho de um serviço root ouvindo em porta incomum, e downloads de arquivos não referenciados (.zip/.txt) no log do Apache.
